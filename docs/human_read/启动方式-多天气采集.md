# 多天气双盘采集

本入口仅采集 `oracle_identity` 控制、`ideal_positions` 感知的数据；投影框可见性继续标记 `unverified`。固定默认 FOV 48，支持单次传入其他 FOV。所有轮次串行，原图仅保存一份，清单在双盘各保存一份。

先在整合工作树中设置路径。解释器仅复用队友已有虚拟环境，不修改队友项目；代码明确从本工作树导入。

```powershell
$codeRoot = (Resolve-Path '.').Path
$runtimeRoot = (Resolve-Path '..').Path
$pythonExe = Join-Path $codeRoot '.venv\Scripts\python.exe'
$dRoot = '..\output\personal_v2\night-capture-20260913-implementation'
$eRoot = 'E:\datasets\_for\_codex\night-capture-20260913-implementation'
$entry = 'import runpy,sys;sys.argv[0]=sys.argv.pop(1)+"/tools/run_official.py";sys.argv.insert(1,"run_dataset_batch");runpy.run_path(sys.argv[0],run_name="__main__")'

& $pythonExe -B -X utf8 -c $entry $codeRoot --help
& $pythonExe -B -X utf8 -c $entry $codeRoot `
  --runtime-root $runtimeRoot --d-root $dRoot --e-root $eRoot --plan-only
```

`--plan-only` 只读并打印轮次和当前容量；不创建轮目录、不启动仿真。有已存批次时同时传 `--resume`。

短测和集成均通过 `--plan-json` 传 JSON 数组。例如先将下面内容保存到批次的 `preflight/H1-01-plan.json`。中文 PowerShell 5.1 脚本须以 UTF-8 BOM 保存，JSON 文件允许有 BOM。

```json
[
  {"run_id":"H1-01","weather":"Clear_Skies","seed":1,"duration":20,"stage":"preflight"}
]
```

```powershell
& $pythonExe -B -X utf8 -c $entry $codeRoot `
  --runtime-root $runtimeRoot --d-root $dRoot --e-root $eRoot `
  --plan-json (Join-Path $dRoot 'preflight\H1-01-plan.json')
```

之后的新计划使用相同两根目录和 `--resume`，它会累积已有记录和占用。H1-02 计划改为 `Partly_Cloudy`，通过以下参数真实转 E：

```powershell
& $pythonExe -B -X utf8 -c $entry $codeRoot `
  --runtime-root $runtimeRoot --d-root $dRoot --e-root $eRoot `
  --plan-json (Join-Path $dRoot 'preflight\H1-02-plan.json') `
  --resume --d-budget-gib 0.01 --e-budget-gib 60
```

后续短测恢复 `--d-budget-gib 60 --e-budget-gib 60`。六天气名称依次为 `Clear_Skies`、`Partly_Cloudy`、`Rain`、`Foggy`、`Snow_Light`、`Sand_Dust_Calm`。身份定向计划可增加 `"layout":"D:/.../diagnostic-layout.json"`，只转交给单轮入口，不修改共享场景。

H3 计划必须使用 `run-01`、`Clear_Skies`、seed 1、duration 200、stage `runs`。完成验收后，下列生产命令默认包含 18 轮；`--resume` 会跳过已有完成的 `run-01`，继续其余 17 轮。

```powershell
& $pythonExe -B -X utf8 -c $entry $codeRoot `
  --runtime-root $runtimeRoot --d-root $dRoot --e-root $eRoot `
  --d-budget-gib 60 --e-budget-gib 60 --min-free-gib 20 `
  --initial-reserve-gib 8 --deadline-hours 8 --fov 48 --resume
```

默认 200 秒预留 8 GiB，20 秒预留 0.8 GiB。取初始预留、历史完整 200 秒轮总目录体积的 1.3 倍、各天气已采产物按实际时长外推至 200 秒的 1.3 倍，择最大值；短测、中止和失败轮有实际时长时也可上调估算。预留不随换盘或新计划降低。预算包含整批根内所有文件：图像、日志、索引、短测和失败证据。

开轮先核查当前盘剩余批次预算和实际可用空间；D 不足再选 E，两者都不足则正常停止且不启动仿真。轮内每 5 秒读取空闲空间、每 15 秒计算当前盘批次占用；剩余空间低于最低值加 0.25 GiB 或占用达到预算时，写入本轮 `stop-request.json`，等待单轮正常收尾，并停止队列。这是周期检查，不能抵御其他进程瞬间耗尽整个磁盘。

存在无关 UE/引擎进程时停止启动，不结束这些进程。Ctrl+C 向当前轮发停止文件并等待其退出。8 小时截止从批次首次创建算起；到点不再开轮，正在进行的轮正常结束。失败或中止轮使用相同 `run_id` 续跑会停止队列，修复后的明确补测应使用新 `run_id`，保留原失败证据。

两盘 `manifest.json` 保存真实绝对输出路径、每次调用的容量检查与停止原因、每轮状态及总体积。每个完整轮的单轮 `summary.json` 由采集入口生成，批处理重新统计包含自身日志的总体积。仅当单轮正常退出且 summary 状态为 `completed` 时记为完成。

低预算拒绝检查应使用两盘批次 `preflight/agent-b` 下独立子目录，并把两盘预算均设为 `0.01` GiB。其清单必须记录 `no_disk_can_fit_next_run` 和 `child_launch_count=0`；这仅验证拒绝启动，不等同于真实换盘、图像采集和轮中停止已经验证。
