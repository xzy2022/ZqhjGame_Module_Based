## 不依赖基准之后官方代码的验证方式

从 `6fc47caeb3ec95eca3f919e4e73335d8d7856265` 导出官方 SDK、官方基线及配置到单独验证目录，不导出旧个人算法包。SDK 与基线共 46 个文件逐字节核对通过。

运行入口的 `--sim-root` 指向该导出目录，`--runtime-root` 指向原发行包以复用引擎和 UE。原生运行资源及 `config` 在基准到当前 HEAD 间没有已提交差异；路线和地形资源已核对，当前拍照配置与基准 JSON 语义一致。验证目录中的两份大 CSV 经内容核对后以硬链接只读复用。

V1、V2、采集父进程和采集子进程分别留下导入审计。所有加载的 `competition.*` 来自基准导出目录，`personal_hf2026.*` 来自新仓库；没有加载原个人算法包。新仓库拥有自己的 `.venv`，未复用队友虚拟环境。

原 SDK 后续唯一修改的采集空转退出钩子，迁为本项目 `sdk_compat.py` 内的子类适配。它只给所选旧 SDK 控制循环的空转分支加入退出检查，保留原评分与收尾；不修改官方文件或官方类。此适配依赖基准接口，升级 SDK 后应重新做实际验证。

