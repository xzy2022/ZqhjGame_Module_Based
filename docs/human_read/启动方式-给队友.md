# 给队友的安装与启动说明

本文命令适用于 Windows 11 和官方 Windows UE 发行包。所有代码命令从 `ZqhjGame_Module_Based` 根目录执行，实验结果写到该目录外的 `..\output\module_based\`。每轮生成带毫秒时间戳和随机后缀的新路径，已有数据集不作为本轮输出目录。

## 1. 首次安装

1. 单独准备完整官方 Windows UE 发行包，完成官方的环境安装及资源下载。确保官方目录包含 `competition`、`python`、`bin\redis-server.exe`、`opensim-sim.exe` 和 `ue-renderer`。本仓库不携带这些运行底座。
2. 将本仓库克隆或解压为官方目录下的 `ZqhjGame_Module_Based`。仓库地址由维护者提供；`ZqhjGame` 是并列的队友项目，运行本项目不需要其虚拟环境。
3. 打开 PowerShell，进入本仓库根目录，执行：

```powershell
git lfs install
git lfs pull
.\setup.ps1 -Vision
```

`setup.ps1 -Vision` 建立本仓库自己的 `.venv` 并安装控制与视觉依赖。若自动选择的 Python 不支持创建虚拟环境，使用 `-Python` 指定已安装的完整 Python 解释器路径。确认 `assets\personal_v2\vision.pt` 已下载为模型文件，而非 Git LFS 文本指针。后续从 `run.cmd` 运行，它会设置本项目源码与官方 SDK 的导入路径；不必手工拼接 Python 路径。

可先检查入口帮助，以下命令不会启动仿真：

```powershell
.\run.cmd control_test_runner --help
.\run.cmd visual_shadow_study --help
.\run.cmd dataset_capture --help
```

## 2. 运行前准备

同一时间只运行一个仿真实验。先结束自己此前的实验；不要结束其他队友正在运行的 UE 或引擎。V2 和采集入口会启动本轮专用 UE，运行它们之前不要另外用官方 `start.ps1` 启动一套 UE。

实验需要 Redis。如果当前已经有可用的本地 Redis，不要重复启动。否则另开一个 PowerShell，进入本仓库根目录后只启动 Redis，并保持此终端打开：

```powershell
..\bin\redis-server.exe `
  --port 6379 `
  --bind 127.0.0.1 `
  --protected-mode no `
  --save "" `
  --appendonly no
```

以下实验命令在另一个终端逐个执行，等待上一轮结束后再启动下一轮。V1 入口启动引擎；V2 与采集入口同时管理本轮 UE 和引擎。命令退出后可检查输出目录中的评分、汇总和日志。

## 3. PersonalV1 控制仿真

此例使用迁入本仓库的静态诱饵场景，运行 200 秒。它验证控制、搜索、协同和评分链，Agent 接收理想感知数据。

```powershell
$runId = (Get-Date -Format 'yyyyMMdd-HHmmss-fff') + '-' + [guid]::NewGuid().ToString('N').Substring(0, 8)
$runOutput = Join-Path '..\output\module_based' ('v1-' + $runId)
.\run.cmd control_test_runner `
  --scenario-json '.\configs\scenarios\coop_decoy\static-decoys.json' `
  --agent 'personal_hf2026.personal_v1:PersonalV1Agent' `
  --duration 200 `
  --seed 1 `
  --output $runOutput
Write-Host "结果目录：$runOutput"
```

首轮只检查启动链时可将 `--duration` 改为 `20`。不要将 20 秒启动检查视为完整任务完成或高分证明。

## 4. PersonalV2 视觉旁路仿真

该入口使用 PersonalV2：V1 产生控制动作，视觉观察器独立记录结果。视觉未接管目标选择和飞行控制，控制分数不等同于视觉识别效果。

```powershell
$runId = (Get-Date -Format 'yyyyMMdd-HHmmss-fff') + '-' + [guid]::NewGuid().ToString('N').Substring(0, 8)
$runOutput = Join-Path '..\output\module_based' ('v2-shadow-' + $runId)
.\run.cmd visual_shadow_study `
  --runtime-root '..' `
  --layout '.\configs\scenarios\coop_decoy\static-decoys.json' `
  --duration 200 `
  --seed 1 `
  --output $runOutput
Write-Host "结果目录：$runOutput"
```

分析时同时查看视觉帧龄、是否实际执行推理、绑定与拒绝记录，不能仅凭程序正常退出判断视觉能力。已有历史结果见 `PersonalV2-视觉旁路说明.md`，其结果属于旧实验。

## 5. 数据集采集的 20 秒试运行

使用全新的输出目录执行一次晴天采集；不会启动旧的 18 轮生产计划，也不使用任何已有数据集作为输出位置。默认最低空闲空间要求为 20 GiB。

```powershell
$runId = (Get-Date -Format 'yyyyMMdd-HHmmss-fff') + '-' + [guid]::NewGuid().ToString('N').Substring(0, 8)
$runOutput = Join-Path '..\output\module_based' ('capture-smoke-' + $runId)
.\run.cmd dataset_capture `
  --runtime-root '..' `
  --layout '.\configs\scenarios\coop_decoy\scenario.json' `
  --weather Clear_Skies `
  --duration 20 `
  --seed 1 `
  --fov 48 `
  --output $runOutput
Write-Host "结果目录：$runOutput"
```

检查本轮 `summary.json`、照片文件和逐帧记录。正常完成与有图像只能证明采集链可运行；投影框可见性标记为 `unverified`，不能直接当作已经人工核验的检测标签。采集采用 `oracle_identity` 控制及 `ideal_positions` 感知，属于数据采集实验。

## 6. 非默认目录和独立 SDK 验证

本仓库不在官方目录下面时，可设置实际路径，然后复用上述命令；V2 和采集的 `--runtime-root '..'` 也应换成实际官方路径：

```powershell
$env:HF2026_SIM_ROOT = 'D:\HF2026\hf2026-sim-windows'
$env:HF2026_RUNTIME_ROOT = $env:HF2026_SIM_ROOT
.\run.cmd --sim-root $env:HF2026_SIM_ROOT control_test_runner --help
```

通常 SDK 和二进制使用同一官方目录。迁移验证需要隔离原仓库个人修改时，可把 `--sim-root` 指向提交 `6fc47caeb3ec95eca3f919e4e73335d8d7856265` 的干净 SDK，把 `--runtime-root` 指向已有完整官方二进制目录。它们是两个独立参数；新仓库保存算法、个人场景及兼容适配，不能把原官方仓库后续个人代码目录偷偷加入搜索路径作为验证前提。

## 7. 旧文档与协作约定

原 `docs` 的 26 个文件（24 份 Markdown 和 2 张图片）完整复制，旧文档只调整路径和入口路径。历史实验输出的绝对路径、日期、数值、分支名、限制与结论均保留，不代表这些旧输出随新仓库分发。旧文档中关于稀疏工作树、复用队友虚拟环境、既往生产批次等文字记录的是当时环境；当前安装和启动以本文为准。

`docs\安装.md` 的脚本主动切换到官方发行包目录，比赛手册也以官方目录为上下文，它们的官方相对路径仍保持这一含义。其他旧实验命令中官方 `start.ps1`、`stop.ps1` 等路径已指向父目录；不要在本仓库根目录照搬旧官方环境操作去修改本仓库文件。

开发前阅读仓库 `AGENTS.md`。每个智能体在自己的 Git 工作树和 `codex/*` 分支开发，由主智能体统一安排仿真；集成到一个 `codex/*` 分支后再串行实际验证。`main` 初始为空提交，最终合并和 GitHub 推送由维护者执行。
