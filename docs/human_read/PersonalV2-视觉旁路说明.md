## 当前范围

`PersonalV2Agent` 先调用原版 V1 产生控制动作，再运行视觉观察器。视觉结果不改变搜索、真假速度过滤、协同、云台、飞行、报告或完成计数。晴天、静态诱饵、理想多目标经纬度和原生主锁检测保持原有控制实验口径。

视觉使用队友冻结 v31 的候选提取、64×64 局部分类网络及权重；未迁移其运动门槛和图像定位。权重随版本存放，运行不导入队友源文件。

每机维护独立候选轨迹和历史；照片源时间由实验入口与局内时间统一，照片只与同一历史时刻的自身姿态、候选经纬度关联。几何采用水平 FOV、机头相对 pan、零相机 roll 假设，不读取车辆高度。框转换为世界水平视线后执行唯一方向匹配；两车共线、多框同轨、正下方退化和快速转动会拒绝绑定。固定高度未参与决定身份。

两张不同帧的高置信度分类在短时窗口内一致才产生旁路身份；过期结果和失效轨迹不会产生身份确认。帧龄门槛为 1.5 秒，角速度门槛为 20 度/秒，均为首版工程参数而非已经优化的阈值。

## 入口和依赖

新增核心文件：`personal_v2.py`、`visual_appearance.py`、`visual_geometry.py`、`visual_shadow_study.py`。离线工具：`analyze_visual_shadow.py`、`replay_visual_shadow.py`。原版 V1 及其控制依赖没有修改。

该工作区采用稀疏检出；`config` 是指向原运行环境同名目录的只读用途目录联接。引擎和 UE 从 `--runtime-root` 指定环境启动。不要在开发工作区修改联接内配置。Python 使用已安装的视觉环境，依赖 PyTorch、NumPy、OpenCV、Pillow、Redis。

以下为今后手动运行的命令；每次使用新的输出目录。当前任务已完成一次 200 秒，不要自动重跑。

```powershell
Set-Location '.'
$RunOutput = '..\output\personal_v2\shadow-' + (Get-Date -Format 'yyyyMMdd-HHmmss')
.\run.cmd visual_shadow_study --runtime-root '..' --duration 200 --seed 1 --output $RunOutput
```

默认布局为本工作区 `configs/scenarios/coop_decoy/static-decoys.json`。同 seed 的诱饵路线仍由原始随机逻辑选择，因此不同运行不是严格相同布局。需要对照时应使用保存的准备后场景和路线。

实验将为本轮启动专用 UE，结束后只关闭本轮进程。2026-09-13 测试时环境中已有另一个 UE；两个 UE 同时存在可能影响 GPU 性能，尚未用单实例对照证明具体影响。

- 独立用 12 个 UE 投影框测试几何：7 个因快速姿态变化拒绝，5 个绑定均与裁判坐标对应同一车辆，方向残差约 0.02～0.38 度。这里使用了已知框，仅是离线几何诊断，不能算真实检测器已成功绑定。
- 对上述 12 个投影区域裁剪做分类，全被网络判为背景。UE 投影框不保证没有遮挡；因此暂不能将其全部计为分类错误。已有画面存在树林和建筑遮挡，仍需检查可见性与模型训练视角差异。

## 后续优先级

1. 先解决照片新鲜度：检查单渲染实例的 GPU 负载与相机帧源时间；不要直接把 1.5 秒门槛放宽到十几秒后宣称实时识别成立。
2. 补齐全程采样，再以人工确认可见的车辆框分别测候选召回和外观分类。先定位遮挡、尺度和视角差异，再决定是否微调模型。
3. 保留无高度方向匹配方案，在更多稳定姿态样本中继续验证；确认不足时保持未知。
4. 这些条件通过之后，才让视觉接管目标选择；当前版本尚不适合进入移动诱饵阶段。

裁判真实身份、UE 投影框仅由实验采集器落盘，Agent 只收到图片、帧号、源时间和原有理想经纬度。所有诊断中的真实标签都在离线使用。
