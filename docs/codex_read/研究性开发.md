
## 背景与定义

在类似科研的项目实现中，一个最终任务会被拆解为多个`子任务`实现或者`假设`。`假设`需要`实验`验证。

- 子任务：路径、要求明确，只是需要一些繁杂的代码书写，并通过`实际测试`确定可用。
- 假设验证：为了排除不确定性来进行的实验，实验结果会用来收敛路线。
- 实际测试：直接去运行一次代码，看看是否有报错或者异常。而不是写很多test去测试逻辑边界，类型检测，数值完备等等。一些情况下，实际测试也会需要启动仿真环境(`仿真测试`)
- 实验：通过日志数据回放进行(`离线实验`)或直接运行仿真环境(`仿真实验`)

因此我需要codex+多agent功能实现。

## 资源限制

1. `离线实验`我的电脑一次可以进行多个，但是`仿真实验`一次只能一个。子agent需要做`仿真测试`或`仿真实验`时需要向主agent发送请求，由它统一管理排队授权。
2. `任务`或`假设`在实现中，可能会发现它们连续多次都失败，这个时候就要权衡是否要放弃，或者退而求其次，进行下一个项。或者如果假设无法完整验证，但是有强证据和信心，那也可以结束。

## 各个 agent 功能说明

主agent：
1. 拆解最终任务为多个`子任务`或`假设`，把`子任务`或`假设`分给子agent处理。
2. 管理子agent的`仿真实验`请求，统一排队授权。仿真实验的时间有三个档位`20s 200s 600s`，根据实际需要选择。
3. 对于子agent的结果进行分析，进行下一步`决策`。

子agent：
1. 规划主agent分配的`子任务`或`假设`，并实现。
2. 当需要做`仿真测试`或`仿真实验`时，向主agent发送请求。


## 要点说明

1. codex需要利用git树管理+子agent功能，去验证各个假设。注意，你需要开分支`codex/***`，不能直接去主分支上改。
2. 由于为了实现各个`子任务`或者`假设`的代码可能会冲突，所以需要各自在自己的分支上，`实际测试`或者`实验`。
3. 当修改的差不多了，合并到一个新的分支`codex/***`，然后再`实际测试`测一下看看有没有冲突。注意，并不是直接合并到主分支。
4. 结束后，解决的问题、未解决的问题、风险都报告一下。

## 禁止

- 禁止执行多次、大批量的600s仿真，这会耗费大量时间和资源。
- 禁止任何向主分支合并的动作，这个需要完成后由我发送指令再进行。
- 多个UE仿真同时进行，以及各个子agent直接启动仿真实验脚本。
