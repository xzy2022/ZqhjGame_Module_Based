# 相机变焦与云台姿态速度场景

此目录只提供专项实验的静态场景种子，不包含 runner。场景固定一架无人机和三辆目标车，排除目标运动与天气变化，专门测量 `set_fov` 和 `set_orientation` 从发令到观测状态稳定所需的仿真时间。

## 名义几何

- 无人机：纬度 `27.0`、经度 `125.0`、海拔 `500 m`、航向 `0°`、初速度 `0 m/s`。
- 初始相机：`FOV=48°`；名义包围圆中心光轴为绝对方位 `0°`、俯仰 `-45°`。
- 三条目标视线在单位球面上组成等边三角形，相对中心光轴的角半径均为 `14°`，相邻视线夹角约 `24.18°`。
- 以平地和目标海拔 `0 m` 计算，A/B/C 的名义绝对 `(方位, 俯仰)` 分别为 `(0°, -31°)`、`(340.768544°, -50.500938°)`、`(19.231456°, -50.500938°)`。
- 三目标在 30°圆形视场内理论余量约 `1°`，因此可直接比较“10°逐目标对准”和“30°包围圆中心”两种策略。

经纬度由相机坐标中的三条视线与 `z=0` 平面求交后换算得到。静态 JSON 无法知道 UE 地形贴地后的真实车辆高度，也无法保证固定翼实现绝对静止；runner 必须用首帧真实经纬高和航向重算各目标的方位、俯仰及夹角，并把这些值作为实际几何依据。

若要严格做“目标接近 48°视场三个边角”的压力档，应由 runner 沿相同三个像面方向动态生成 `20°` 角半径的场景。该档相邻视线夹角约 `34.46°`，可以检验 10°循环的跨目标调姿速度，但目标会超出 30°视场半角，不能同时作为“30°中心包含三目标”的对照。两项要求在圆形 FOV 定义下几何上不能同时满足。

## 建议的 20 秒命令时间表

所有姿态命令应以每帧真实机头航向换算为相对 `pan`；下表的角度仅是无人机保持航向 `0°` 时的名义值。

| 仿真时间 | FOV | 光轴命令 | 目的 |
| --- | ---: | --- | --- |
| `0.0–2.0 s` | 48° | 中心 `(0°, -45°)` | 启动稳定，并确认三目标实际都在视场内 |
| `2.0–3.0 s` | 10° | 保持中心 | 单独测量 `48→10°` 变焦阶跃 |
| `3.0–5.0 s` | 10° | A `(0°, -31°)` | 第一次逐目标对准 |
| `5.0–7.0 s` | 10° | B `(-19.231456°, -50.500938°)` | 测量 A→B 调姿 |
| `7.0–9.0 s` | 10° | C `(19.231456°, -50.500938°)` | 测量 B→C 调姿 |
| `9.0–11.0 s` | 10° | A | 测量 C→A 调姿 |
| `11.0–13.0 s` | 10° | B | 第二轮稳定性样本 |
| `13.0–15.0 s` | 10° | C | 第二轮稳定性样本 |
| `15.0–17.0 s` | 30° | 中心 | 30°包围圆中心策略，并测量 `10→30°` |
| `17.0–19.0 s` | 48° | 保持中心 | 单独测量 `30→48°` 变焦阶跃 |
| `19.0–20.0 s` | 10° | 保持中心 | 复测 `48→10°`，随后结束 |

建议每帧记录命令时间、真实 `pan/tilt/fov`、机体航向、三目标真实视线角和图像时间戳。完成判据可先用 `|FOV-FOV_cmd|≤0.1°` 与光轴角误差 `≤0.5°`，并连续保持 `0.2 s`；最终报告同时给出首次进入阈值时间、稳定时间、超调量和是否丢帧，不要仅依据配置中的速率上限推断执行速度。

## runner 接入边界

参考 `nearest_selection_study.make_scenario`：从此场景深拷贝实体、禁用父类随机路线准备，并在启动时再次向三辆车发送 `set_speed(0)`。若首帧显示无人机仍移动，应让 runner 在实验期间重复发送 `set_speed(0)`；若引擎仍强制固定翼最低速度，则退化为小半径盘旋，并逐帧按真实位姿重算指向，不能把静态名义角度当成测量真值。
