

背景：跑一次完整的600s仿真时间很长，尤其是可能需要跑很多次才能覆盖比较多的情况。因此我自己集中跑完多次仿真实验后，需要codex去分析这些日志查明各种发现的bug或者问题。

任务：
1. codex需要利用git树管理，去排查这些Bug。注意，你需要开分支`codex/***`，不能直接去主分支上改。
2. 由于这些Bug或问题的修改代码可能相互冲突，所以需要各自在自己的分支上，利用离线日志回测。
3. 当修改的差不多了，合并到一个分支`codex/***`，然后再回测一下看看有没有冲突。注意，并不是直接合并到主分支。
4. 最后确定没问题，再进行一次完整的仿真(200s 600s根据情况决定)，根据新日志看看修改的怎么样。

注意：
1. 这些Bug或者问题，并不要求全都给解决，因为各个问题的难度可能不同，不要死磕一个。
2. 结束后，把修成功的问题和没解决的问题都报告一下，后续由人工决定做什么。

禁止：
- 禁止执行多次、大批量的600s仿真，这会耗费大量时间和资源。
- 禁止任何向主分支合并的动作，这个需要完成后由我发送指令再进行。
